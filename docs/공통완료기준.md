| Gateway와 독립 Service 2개 이상이 각자의 소유 DB와 함께 실행된다 | 충족 | Gateway + 4개 서비스, core-db 안의 `auth_db`·`festival_db`·`reservation_db`·`payment_db` 스키마와 서비스별 DB 계정(`mysql-init/core-db`) |
| 다른 Service DB를 직접 조회·JOIN·갱신하지 않는다 | 충족 | 각 서비스 datasource가 자기 스키마만 가리키고, 다른 서비스 데이터는 내부 API로만 조회(서비스 경계 문서) |
| 핵심 사용자 흐름, 인증·인가·Resource 소유권, 동기 호출 실패를 검증한다 | 충족 | 서비스별 Acceptance Test, Contract Test(`ReservationServiceClientTest`·`FestivalStockClientTest`·`HelperSessionClientTest`), 실패 복구 Test(`HostApplicationReviewAcceptanceTest`·`SeatedFestivalPublishRetryTest`·`PaymentCompensationAcceptanceTest`·`PaymentSyncSchedulerTest`) |
| 동기 호출의 멱등성·상태 전이·Timeout과 Trace ID 전달을 정하고 서비스별 Local Transaction과 통합 Test로 근거를 남긴다 | 충족 | 멱등키(applicationId·ticketTypeId·Idempotency-Key·webhook_id·PG 취소 ID), 중간 상태(APPROVAL_PENDING·PUBLISH_PENDING)와 재시도 배치, 서비스별 ClientConfig의 connect·read Timeout, X-Trace-Id를 서비스 로그와 내부 호출에 전달(`TraceIdFilterTest`) |
| `docker compose` 한 번으로 새 환경에서 재현한다 | 충족 | `cp .env.example .env && docker compose -f docker-compose.yml -f docker-compose.local.yml up -d --build` — 2026-09-29 새 clone에서 8개 컨테이너 기동과 스모크 확인(실행·배포 가이드) |
| Notion의 15종 원본이 현재 코드·Migration·OpenAPI·실행 결과와 일치하고, 최근 Review 뒤 Git Snapshot과 동기화되어 있다 | 부분 충족(Migration·OpenAPI 파일 없음) | 2026-09-29 Notion을 코드·실행 결과 기준으로 수정. `docs/*.md` 스냅샷은 Notion 반영 뒤 다시 내보내야 동기화됨. Migration·OpenAPI 파일은 저장소에 없어 비교 대상 없음 |
| 미실행은 `NOT_RUN`, 실패는 원인·담당자·다음 조치를 기록한다 | 충족 | 테스트 체크리스트·실행·배포 가이드의 NOT_RUN 기록(실제 PortOne 결제 완료, 메일·소셜 로그인) |
| Story는 모든 Task와 Acceptance Criteria가 완료되고 통합된 뒤에만 Done으로 옮긴다 | 부분 충족 | Story 9·11은 AC 상세화 없이 종료, Story 12는 NOT_PLANNED로 종료(현황 코멘트는 2026-09-29 추가) |
