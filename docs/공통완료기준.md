2026-09-29 코드 기준 재확인 결과를 항목마다 적었다. 체크는 코드·실행 근거로 충족이 확인된 항목에만 했다.

- [x]  Gateway와 독립 Service 2개 이상이 각자의 소유 DB와 함께 실행된다. — 충족: gateway와 auth·festival·reservation·payment 4개 서비스. MySQL 인스턴스는 `core-db` 하나지만 스키마(`auth_db`, `festival_db`, `reservation_db`, `payment_db`)와 서비스 계정을 서비스마다 분리했다.
- [x]  다른 Service DB를 직접 조회·JOIN·갱신하지 않는다. — 충족: 각 서비스 datasource는 자기 스키마만 가리키고, init 스크립트는 서비스 계정에 자기 스키마 권한만 준다. 다른 스키마 이름을 쓰는 Java 코드가 없다. 다른 서비스 데이터는 내부 API로만 가져온다.
- [ ]  핵심 사용자 흐름, 인증·인가·Resource 소유권, 동기 호출 실패를 검증한다. — 부분 충족: 가입·신청·심사·등록·예매·결제·체크인·정산 흐름과 401·403·소유권·동기 호출 실패(역할 부여 실패, 재고 복구 실패, 웹훅 일시 장애, 확정 거절 결제)를 Acceptance Test로 검증하고 2026-09-29 전체 실행이 PASS였다. 다만 좌석 생성 내부 호출(`POST /internal/v1/seats`) 실패·재시도 경로는 자동 테스트가 없다.
- [ ]  동기 호출의 멱등성·상태 전이·Timeout과 Trace ID 전달을 정하고 서비스별 Local Transaction과 통합 Test로 근거를 남긴다. — 부분 충족: 멱등 키(역할 부여 applicationId, 좌석 생성 ticketTypeId, 결제 취소 멱등 키)와 중간 상태(APPROVAL_PENDING, PUBLISH_PENDING)·재시도 스케줄러, 호출별 Timeout(예: festival → auth connect 1초·read 5초, 게이트웨이 도우미 세션 확인 3초, PortOne read 2초)은 코드에 있다. Trace ID는 게이트웨이가 `X-Trace-Id`를 만들어 하위 서비스로 넘기는 데까지만 있고, 서비스가 로그에 남기거나 서비스 간 호출로 다시 전달하지 않는다. 서비스를 함께 띄우는 통합 테스트는 없다.
- [ ]  `docker compose` 한 번으로 새 환경에서 재현한다. — 미충족: 백엔드 이미지는 `build/libs/*.jar`를 복사하므로 `./gradlew bootJar`가 먼저 필요하고, 루트 `.env` 작성이 선행돼야 하며, nginx는 운영 인증서 경로에 의존한다. 전체 compose 기동은 실행·배포 가이드에 NOT_RUN으로 기록돼 있다.
- [ ]  Notion의 15종 원본이 현재 코드·Migration·OpenAPI·실행 결과와 일치하고, 최근 Review 뒤 Git Snapshot과 동기화되어 있다. — 미충족: Migration과 OpenAPI 파일은 존재하지 않는다(위 N/A). Git `docs/`에는 15종 중 12종 스냅샷이 있고 요구사항·공통 완료 기준·화면 설계 스냅샷은 없다(2026-09-29 기준).
- [x]  미실행은 `NOT_RUN`, 실패는 원인·담당자·다음 조치를 기록한다. — 충족: 테스트 전략·테스트 체크리스트·실행·배포 가이드에 실행하지 않은 Demo·compose 기동을 NOT_RUN과 사유로 기록했다. 2026-09-29 실행에서 실패한 테스트는 없었다.
- [ ]  Story는 모든 Task와 Acceptance Criteria가 완료되고 통합된 뒤에만 Done으로 옮긴다. — 미충족: Sprint Review·Retrospective 문서에 따르면 Story 9(#38)·Story 11(#40)은 이슈 본문 AC가 "상세화 예정"인 채 종료됐고, Story 1(#22)은 하위 프론트 Task 일부가 Sprint 2 마일스톤에 남아 있었다.
