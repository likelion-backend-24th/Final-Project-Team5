# 1. 사용자 문제·Product Goal·성공 기준

| 항목 | 정의 |
| --- | --- |
| 사용자 문제 | 페스티벌 참가자와 주최자는 여러 페스티벌의 예매 정보가 채널마다 따로 관리되는 상황에서 티켓 예매·발권 과정이 하나로 이어지지 않기 때문에, 참가자는 예매 혼선·중복 예매를, 주최자는 판매 현황 파악 지연과 정산 오류를 겪는다. |
| Product Goal | 페스티벌 참가자와 주최자가 하나의 플랫폼에서 티켓 예매부터 발권까지 혼선 없이 진행하며, 장기적으로 여러 페스티벌을 신뢰하고 예매할 수 있는 생태계에 도달한다. |

**Release 성공 기준**

아래 항목은 Release를 평가하는 기준이다. 체크 표시는 달성 여부를 뜻하지 않으며, 달성 근거는 Sprint Review 문서의 "Release 성공 기준 대비 근거"와 테스트 체크리스트 문서에서 확인한다.

- [ ]  참가자가 원하는 티켓을 정확한 수량으로 예매하고, 예매 내역을 확인할 수 있다.
- [ ]  동일 티켓이 실제 재고보다 많이 팔리는 중복·초과 판매가 발생하지 않는다.
- [ ]  결제 실패·취소 시 티켓 재고가 정확히 복구되고, 참가자에게 실패 사유가 안내된다.
- [ ]  권한·소유권이 보장된다: 로그인·역할이 맞지 않는 요청은 거절되고, 주최자와 부스 운영자는 본인 소유 페스티벌·부스만, 도우미는 배정된 페스티벌의 입장 검증만 할 수 있다.
- [ ]  결제·환불 거래가 일관된다: 예매 확정·환불·정산 금액이 실제 결제 기록과 일치하고, 같은 예매에 중복 결제가 생기면 나중 결제는 자동 전액 환불되어 정산에서 빠진다.

# 2. 대상 사용자·Release 범위

## 대상 사용자

| Actor | 목표·책임 |
| --- | --- |
| 플랫폼 운영자 (ADMIN) | 플랫폼에 등록된 페스티벌들을 관리하고, 주최 신청과 페스티벌 등록·행사 취소를 심사하며, 회원 정지·해제와 전체 결제·정산 현황을 관리한다. 가입이나 신청으로는 될 수 없고, 운영자가 DB에서 계정의 역할을 직접 지정한다. |
| 페스티벌 주최자 (HOST) | 자신이 담당하는 페스티벌을 등록하고, 티켓 종류·가격·수량을 설정하며, 도우미를 초대하고, 예매 현황·현장 체크인·정산을 관리한다. 주최 신청이 승인되면 이 역할이 된다. |
| 현장 입장 도우미 (HELPER) | 주최자의 이메일 초대를 수락해 활성화되는 임시 계정이다. 배정된 페스티벌의 QR·입장 코드 검증과 입장 현황 조회만 할 수 있고, 예매·결제 등 다른 기능은 쓸 수 없다. 행사 종료 뒤 자동 삭제된다. |
| 부스 운영자 (STOREHOST) | 페스티벌마다 부스를 하나 개설해 운영 상태를 바꾸고, 대기 신청한 참가자의 순번을 호출한다. 전용 신청·부여 기능이 없어 운영자가 DB에서 역할을 직접 지정한다. |
| 참가자 (USER) | 페스티벌을 검색·조회하고 티켓을 예매·결제하며, 예매 내역을 확인하고 필요 시 취소·환불을 요청한다. 부스 대기 신청과 AI 추천 챗봇도 쓸 수 있다. 예매·결제는 도우미를 뺀 로그인 회원이면 역할과 관계없이 할 수 있다(의도된 동작). |
| 방문자 | 로그인 없이 공개된 페스티벌 목록·상세, 부스 목록, 좌석 배치도, 이용약관·개인정보처리방침을 둘러보고, 예매하려면 회원가입한다. |

# 3. 사용자 시나리오

적용 Sprint는 해당 기능이 main에 처음 반영된 커밋 날짜 기준이다: Sprint 1(08-31~09-06), Sprint 2(09-07~09-13), Sprint 3(09-14~09-20), Week 4 안정화(09-21~09-29). 관련 작업의 Story 번호는 Sprint Review 문서에 적힌 번호를 쓰고, 번호가 없는 항목은 "미확인 - 팀 확인 필요"로 표시했다.

# 5. 업무 용어

| 업무 용어 | 제품에서 사용하는 의미 |
| --- | --- |
| 방문자 | 아직 회원가입하지 않고 플랫폼을 둘러보는 사용자 |
| 참가자 | 회원가입 완료 후 예매·결제가 가능한 회원 |
| 주최 신청 | 회원이 페스티벌 개최 권한을 얻기 위해 운영자에게 제출하는 심사 요청 |
| 주최자 권한(Role) | 신청 승인 뒤 기존 계정의 역할이 HOST로 바뀌어 얻는, 페스티벌 등록·관리가 가능한 권한. 계정은 역할을 하나만 가진다 |
| 도우미(HELPER) | 주최자가 이메일로 초대해 현장 입장 검증만 맡기는 임시 계정. 행사 종료 뒤 자동 삭제된다 |
| 부스 운영자(STOREHOST) | 페스티벌 안에서 부스를 개설·운영하고 대기 순번을 호출하는 계정 |
| 페스티벌 공개 | 승인된 주최자의 페스티벌이 방문자·참가자 목록에 노출되는 상태 |
| 예매(신청) | 참가자가 원하는 티켓 종류·수량을 선택해 만드는 대기(Pending) 상태의 요청 (결제 전) |
| 재고 | 티켓 종류별로 판매 가능한 남은 수량 |
| Access Token | API 요청 시 인증에 사용하는 단기 유효 토큰 |
| Refresh Token | Access Token 만료 시 재발급에 사용하는 장기 유효 토큰(서버 보관, 재발급마다 교체) |
| 대기열 | 정원 임박 시 동시 신청을 순서대로 처리하기 위해 대기 상태로 줄 세우는 구조. 후속 Product Backlog 후보이며 현재 Release에는 없다 |
| 예매 확정 | 결제 성공 후 예매 상태가 Pending에서 Confirmed로 바뀌는 것 |
| QR 티켓(모바일 티켓) | 결제 확정된 예매에 발급되는, 현장 입장 확인용 코드. QR을 쓸 수 없을 때는 입장 코드를 입력한다 |
| 체크인 | 현장에서 QR을 스캔하거나 입장 코드를 입력해 참가자의 입장을 확인하는 절차 |
| 취소·환불 | 확정된 예매를 참가자가 철회하고 결제 금액에서 위약금을 뺀 금액을 돌려받는 절차 |
| 위약금 | 참가자 본인 환불 때 행사 시작까지 남은 기간에 따라 환불 금액에서 빼는 비율(0%·10%·20%·30%) |
| 행사 취소 | 주최자가 요청하고 운영자가 승인해 행사 전체를 취소하는 것. 모든 결제가 위약금 없이 전액 환불된다 |
| 정산 | 페스티벌별 매출·수수료를 집계해 주최자에게 지급할 금액을 산출하는 절차 |
| 정산 라인 | 정산에 포함되는 결제 한 건의 매출·수수료·환불 금액 기록 |
| 수수료 환입 | 환불로 줄어든 매출만큼 처음 계산한 수수료를 돌려받는 금액 |
| 정산 조정 | 정산 뒤 생긴 환불을 기존 정산을 고치지 않고 남기는 기록. 지급 전 조정(PRE_PAYMENT)과 지급 후 조정(POST_PAYMENT)이 있다 |
| 정산 보류 | 결제·예매·결제사 기록이 맞지 않아 금액을 확정하지 않고 멈춘 정산 상태 |
| 부스 | STOREHOST가 페스티벌마다 개설하는 부스. 상태는 대기(WAITING)·운영중(OPEN)·마감(CLOSED) 3가지 |
| 대기 신청 | 해당 페스티벌 티켓을 보유한 참가자가 운영중인 부스에 자리를 미리 확보하는 행위 |
| 대기번호(순번) | 대기 신청 순서대로 부여되는 선착순 번호. 부스별로 독립적으로 증가 |
| 티켓 판매 방식(TicketMode) | STANDING(수량만 지정해 구매)과 SEATED(구역·좌석을 직접 선택해 구매) 두 가지 |
| 좌석(Seat) | SEATED 티켓종류에 속한 개별 좌석. 구역(zone)·열(rowLabel)·번호(seatNumber)로 식별 |
| 좌석 상태 | AVAILABLE(선택 가능)·HELD(다른 참가자가 선점 중)·SOLD(구매 완료) 3가지 |
| AI 추천 챗봇 | 참가자가 조건을 말하면 공개 중인 페스티벌 중 맞는 것을 골라 추천하는 대화형 도우미(Google Gemini 연동) |
| 무대 배치(FestivalStageLayout) | 페스티벌의 구역 배치 방식. 전면형(FRONT_STAGE, 그리드)과 중앙형(CENTER_STAGE, 도넛형) 두 가지, 모든 페스티벌이 필수로 지정 |
| 구역 위치 | 티켓종류가 화면에서 배치되는 순서 정보. 전면형은 행·열 좌표(positionRow·positionCol), 중앙형은 각도(positionAngle)로 정한다 |
| 대기 호출 | STOREHOST가 부스 대기열에서 다음 순번을 불러들이는 행위. 해당 참가자에게는 챗봇 알림으로 전달된다 |
| 부스 알림(알림 피드) | 챗봇 버튼을 펼친 뒤 열리는 별도 패널. 내 대기 순번이 호출된 이력을 목록으로 보여주며 입력창은 없다. 추천 챗봇 대화와는 섞이지 않는다 |
