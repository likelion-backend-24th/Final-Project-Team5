# 1. 사용자 문제·Product Goal·성공 기준

| 항목 | 정의 |
| --- | --- |
| 사용자 문제 | 페스티벌 참가자와 주최자는 여러 페스티벌의 예매 정보가 채널마다 따로 관리되는 상황에서 티켓 예매·발권 과정이 하나로 이어지지 않기 때문에, 참가자는 예매 혼선·중복 예매를, 주최자는 판매 현황 파악 지연과 정산 오류를 겪는다. |
| Product Goal | 페스티벌 참가자와 주최자가 하나의 플랫폼에서 티켓 예매부터 발권·입장·정산까지 혼선 없이 진행하며, 장기적으로 여러 페스티벌을 신뢰하고 예매할 수 있는 생태계에 도달한다. |

**Release 성공 기준** (근거는 Sprint Review 문서의 "Release 성공 기준 대비 근거")

- [x]  참가자가 원하는 티켓을 정확한 수량으로 예매하고, 예매 내역을 확인할 수 있다.
- [x]  동일 티켓이 실제 재고보다 많이 팔리는 중복·초과 판매가 발생하지 않는다.
- [x]  결제 실패·취소 시 티켓 재고가 정확히 복구되고, 참가자에게 실패 사유가 안내된다.

# 2. 대상 사용자·Release 범위

## 대상 사용자

| Actor (Role) | 목표·책임 |
| --- | --- |
| 플랫폼 운영자 (ADMIN) | 주최 신청과 페스티벌 공개를 심사하고, 행사 취소를 승인·반려하며, 회원·주최자·페스티벌 운영 현황과 정산을 관리한다. |
| 페스티벌 주최자 (HOST) | 자신이 주최하는 페스티벌을 등록하고 티켓 종류·가격·수량·좌석을 설정하며, 도우미를 초대해 현장 입장을 관리하고 정산을 확인한다. |
| 현장 도우미 (HELPER) | 주최자가 초대한 임시 계정으로, 배정된 페스티벌 1개의 현장 입장 검증만 한다. |
| 부스 운영자 (STOREHOST) | 공개 중인 페스티벌에 부스를 열고 대기열 순번을 호출한다. |
| 참가자 (USER) | 페스티벌을 검색·조회하고 티켓을 예매·결제하며, QR로 입장하고 필요 시 취소·환불을 요청한다. 부스 대기 신청과 AI 추천 챗봇을 쓴다. |
| 방문자 | 로그인 없이 공개된 페스티벌 목록·상세·부스·좌석 배치를 둘러보고, 예매하려면 회원가입한다. |

# 5. 업무 용어

| 업무 용어 | 제품에서 사용하는 의미 |
| --- | --- |
| 방문자 | 아직 회원가입하지 않고 플랫폼을 둘러보는 사용자 |
| 참가자 | 회원가입 완료 후 예매·결제가 가능한 회원(USER) |
| 주최 신청 | 회원이 페스티벌 개최 권한을 얻기 위해 운영자에게 제출하는 심사 요청 |
| 주최자 권한(Role) | 신청 승인 뒤 계정의 role이 HOST로 바뀌어 페스티벌 등록·관리를 할 수 있는 권한 |
| 도우미(HELPER) | 주최자가 이메일로 초대한 임시 계정. 배정된 페스티벌 1개의 현장 입장 검증만 한다 |
| 부스 운영자(STOREHOST) | 페스티벌에 부스를 열고 대기열을 운영하는 입점 사업자. 부여 API 없이 DB에서 role을 지정한다(로컬 재현 환경은 시드 계정) |
| 페스티벌 공개 | 운영자가 공개 승인하고 좌석 생성까지 끝나 방문자·참가자 목록에 노출되는 상태(PUBLISHED) |
| 예매(신청) | 참가자가 티켓 종류·수량(또는 좌석)을 선택해 만드는 대기(PENDING) 상태의 요청. 결제 전 10분간 재고를 확보한다 |
| 재고 | 티켓 종류별로 판매 가능한 남은 수량(festival-service의 remain_quantity) |
| Access Token | API 요청 시 인증에 사용하는 1시간 유효 토큰 |
| Refresh Token | Access Token 재발급에 쓰는 14일 유효 토큰(HttpOnly 쿠키, DB에는 해시 저장, Rotation 적용) |
| 예매 확정 | 결제 성공 후 예매 상태가 PENDING에서 CONFIRMED로 바뀌고 QR·입장 코드가 발급되는 것 |
| QR 티켓·입장 코드 | 결제 확정된 예매에 발급되는 현장 입장 확인용 코드. QR이 안 될 때 `XX-XXXX-XXXX` 형식 입장 코드를 입력한다 |
| 체크인(입장) | 현장에서 QR·입장 코드를 검증해 참가자의 입장을 기록하는 절차 |
| 취소·환불 | 확정된 예매를 참가자가 철회하고 위약금을 뺀 금액을 돌려받는 절차(부분 환불 가능) |
| 행사 취소 | 주최자가 신청하고 운영자가 승인하면 해당 행사의 모든 결제를 위약금 없이 전액 환불하는 절차 |
| 보상 환불 | 결제는 승인됐지만 예매 확정이 거절된 결제를 자동으로 전액 취소하는 처리 |
| 결제 결과 재조회 | 완료 요청·웹훅이 오지 않은 결제를 배치가 PortOne에 다시 물어 결과를 반영하는 처리 |
| 정산 | 행사 종료 24시간 뒤 페스티벌별 매출·환불·수수료를 집계해 주최자 지급액을 산출하고 운영자가 확정·지급 기록하는 절차 |
| 매출·환불 원장 | 정산 라인(결제 1건당 1개)과 뒤늦은 환불을 반영하는 정산 조정 기록 |
| 부스 | STOREHOST가 공개 중인 페스티벌마다 1개 개설하는 부스. 상태는 대기(WAITING)·운영중(OPEN)·마감(CLOSED) |
| 대기 신청·대기번호 | 해당 페스티벌 티켓 보유 참가자가 운영중인 부스에 받는 선착순 번호. 부스별로 독립 증가 |
| 대기 호출 | STOREHOST가 다음 순번을 부르는 행위. 참가자에게는 챗봇 위젯의 부스 알림으로 전달된다 |
| 티켓 판매 방식(TicketMode) | STANDING(수량만 지정)과 SEATED(구역·좌석을 직접 선택) |

| AI 추천 챗봇·AI 등록 초안 | Google Gemini를 쓰는 두 기능. 챗봇은 참가자에게 공개 페스티벌을 추천하고, 등록 초안은 주최자의 자유 문장에서 등록 폼 값을 제안한다 |
