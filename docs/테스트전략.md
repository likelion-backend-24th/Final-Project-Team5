## 테스트 수준과 도구

| 수준 | 이 프로젝트에서의 의미 | 도구·설정 |
| --- | --- | --- |

| Component | Spring 컨텍스트와 H2 DB를 띄워 스케줄러·리포지토리·서비스를 함께 검증(HTTP 없음) | `@SpringBootTest`, `@DataJpaTest` |

| 프론트 Component | 화면·컴포넌트·API 어댑터를 사용자 동작 기준으로 검증. API 모듈은 `vi.mock`으로 대체 | Vitest 5, jsdom, Testing Library(React, user-event) |

## 테스트 데이터·격리·복구 규칙

- 백엔드 DB: 각 서비스 `src/test/resources/application.yaml`이 H2 in-memory(`jdbc:h2:mem:<서비스>_db;MODE=MySQL`)와 `ddl-auto: create-drop`을 쓴다. 테스트는 운영·로컬 MySQL(core-db)에 접속하지 않는다. gateway는 테스트용 yaml이 없고 Spring 컨텍스트 없이 필터·클라이언트만 검증한다.
- 예외: auth-service `HelperAccountServiceTest`는 `HELPER_TEST_DB_*` 환경 변수를 주면 외부 DB로도 실행할 수 있다(기본은 H2).
- 격리: 28개 테스트 파일이 `@BeforeEach`(일부는 `@AfterEach`도)에서 리포지토리 `deleteAll()`로 데이터를 비운다. `@Transactional` 롤백·`@DirtiesContext`·`@Sql`은 쓰지 않는다. 필요한 사용자·페스티벌·예매는 각 테스트가 직접 만든다(공용 Fixture 파일 없음). 배치 대상 시각을 맞추려고 `PaymentSyncSchedulerTest`는 `created_at`을, `SeatedFestivalPublishRetryTest`는 `updated_at`을 `JdbcTemplate`으로 과거로 옮긴다.
- 스케줄러: payment-service 테스트 설정은 정산·행사 취소 환불·웹훅 재시도·보상 환불·결제 재조회 스케줄러와 가상계좌 데모 입금을 끈다(`*.scheduling-enabled: false`, `payment.demo-deposit.enabled: false`). 스케줄러 동작은 해당 스케줄러 테스트에서 메서드를 직접 호출해 검증한다.
- 외부 연동: 메일·OAuth·PortOne·Gemini 설정은 테스트 전용 더미 값을 쓰고, 실제 외부 호출은 `@MockitoBean`이나 스텁 서버로 대체한다. 이미지 업로드 테스트(`ImageUploadValidationTest`)는 JUnit `@TempDir`에만 파일을 쓴다.
- 프론트: `vitest.config.js`가 jsdom 환경과 `src/test/setup.js`를 쓰며, setup이 테스트마다 `cleanup()`, `localStorage.clear()`, 모듈 전역 캐시(`clearQueryCache`)를 비운다.
- 복구: 테스트 DB는 JVM 종료와 함께 사라지므로 별도 복구 절차가 없다. 이번 실행 전후로 저장소의 추적 파일과 무시 대상 목록(`git status --short --ignored`)에 변화가 없음을 확인했다(빌드 출력 폴더 제외).
