| 항목 | 기록 |

| 관련 계약·Test | 자동 테스트 없음(인프라 설정). 근거 커밋 `742bb99`, 설정 `docker-compose.small.yml` 주석, 각 서비스 `application.yaml`의 `hikari.maximum-pool-size` |
| 재현·증상 | 배포 후 payment-service가 DB 연결 실패와 "Too many connections"로 재시작을 반복했다. |
| 확인한 원인 | 커밋 본문에 기록된 3가지. (1) core-db 볼륨이 payment_db 도입 전부터 있어 `mysql-init/core-db/03-payment-db.sql`이 한 번도 실행되지 않아 스키마·계정이 없었다. (2) payment-service Dockerfile만 exec-form ENTRYPOINT라 `JAVA_OPTS`(힙 상한)가 적용되지 않았다. (3) MySQL `max-connections=30`이 기존 3개 서비스의 기본 풀(10개씩)로 이미 차 있었다. |
| 조치 | 운영 DB에 init 스크립트를 수동 실행(현장 조치), payment-service Dockerfile을 다른 서비스와 같은 shell-form(`sh -c "exec java $JAVA_OPTS -jar app.jar"`)으로 통일, 서비스별 Hikari 풀 5개와 core-db `--max-connections=60`으로 조정. |
| 정상·실패 회귀 | 코드상 확인: 백엔드 Dockerfile 5개 ENTRYPOINT 동일, 4개 서비스 `maximum-pool-size: 5`, `docker-compose.small.yml`의 `--max-connections=60`. 자동 회귀 테스트는 없음 |
| Backlog·설계 조정 | 실행·배포 가이드에 "core-db 볼륨이 이미 있으면 init 스크립트가 다시 실행되지 않는다"를 기록. 1GB 서버용 설정은 `docker-compose.small.yml`로 분리 유지 |
